# 13 — Mobile "app" plan: every page as an iOS-style application screen (owner's order, 2026-10-16, 45-minute sprint)

The owner wants EVERY page of the website, on a phone or tablet, to behave like an application opened from the launcher: the launcher icon is the app,
the page is its screen. Same content as the laptop site, a completely separate iOS-style design. The laptop/desktop site must not change at all.

## Hard rules (every agent reads these first)
1. **Laptop/desktop is untouched.** Never edit anything under `src/app/(site)`, `src/app/admin`, `src/components/site/**` outside `src/components/site/mobile/**`,
   `src/app/globals.css`, `src/styles/**`. Allowed: `src/app/(m)/**`, `src/components/site/mobile/**`, `src/lib/mobile-*`, `tools/`, `brain/`.
2. **Content = the laptop content.** Read it from the same CMS source as the laptop pages (`getPublishedPage(slug)` in `src/lib/cms/queries.ts`, defaults in
   `src/lib/cms/content/*.ts`, contact data in settings). Never invent text, numbers, clients, prices. Layout/design is new; words are the same.
3. **Server chooses the app**: phones/tablets are rewritten to `/m/<path>` by `src/proxy.ts` for every path in `MOBILE_READY`. `MOBILE_READY` is generated by
   `node tools/sync-mobile-ready.mjs` from the folders `src/app/(m)/m/<path>/page.tsx` (do not edit the generated file by hand). A mobile page has the SAME
   public path as its laptop page (e.g. `(m)/m/seo/page.tsx` for `/seo`, `(m)/m/headless-CMS-devlopment-services/page.tsx`).
4. **Design = iOS 26** (liquid glass, big titles, grouped lists, SF-like hierarchy), one design system for all pages, Poppins font (+ the launcher's chosen font via `.lnc`
   is NOT used inside pages), theme-relative colours only: `hsl(calc(var(--th) + N) calc(S% * var(--ts)) L%)` — never a hard-coded violet/pink.
   Paragraphs >= 16px, labels >= 12px on phone, touch targets >= 44px, contrast >= 4.5.
5. **CSS**: a page's CSS lives next to the page (`(m)/m/<path>/page.css`, imported by that page.tsx, class prefix unique to the page) or in the design system
   (`src/components/site/mobile/app/app.css`, prefix `ma-`). Never put CSS in `globals.css`. Do not edit another agent's files.
6. **Light**: no 3D / canvas / GSAP / three.js on mobile pages. CSS transitions only (`transform`, `opacity`). Images: `next/image`, no unoptimised heavy images.
7. **Gates before anything is merged**: `npx tsc --noEmit`, `npx eslint <changed folders>`; the orchestrator also runs `npm run build` (webpack) before a push to `main`.
8. **Git**: work in your own worktree/branch; commit small with a clear message; the orchestrator merges into `main` and pushes. Only `main` exists on GitHub.
9. Replies/notes for the owner are in short Gujarati-English; code comments in English, plain.

## Architecture (built by Agent 1, then used by everyone)
- `src/components/site/mobile/app/` — the design system ("MobileApp kit"): `AppScreen` (status-safe area, large title that collapses, back button to the launcher,
  swipe-back feel), `Section`, `GroupedList`/`ListRow`, `Card`, `Chip`, `Button`, `Accordion` (FAQ), `Stepper`/timeline, `Hero`, `Gallery`, `CtaBar` (sticky Call / WhatsApp /
  Message), `Tabs`. All prefixed `ma-`, tokens in `app.css`.
- `src/components/site/mobile/pages/render.tsx` — `renderMobilePage(slug)` reads the same CMS page as the laptop and maps EVERY section type
  (`SECTIONS` in `src/lib/cms/sections.ts`, ~45 types) to a mobile component in `src/components/site/mobile/pages/sections/<type>.tsx` (one file per type).
  Unknown/3D-only sections fall back to a clean card with the same title + text.
- `src/app/(m)/m/<path>/page.tsx` — 3-line pages: `export default () => renderMobilePage("<slug>")` + metadata from the CMS (canonical = the laptop URL).
- Tech pages (6 pages with their own components `TechPage`) and the bespoke pages (seo, meta/physical marketing, brand dev, end-to-end, graphics, metaverse, about, team,
  careers) have their data in `src/lib/cms/content/*` or `src/components/site/**/**-data.ts`; Agent 2 instances give them page-specific app screens.

## Process per page (Task 4)
1. **Read**: the laptop page (`/slug` in the browser, its CMS content) → list its sections and its real text.
2. **Plan**: one line per screen section: which kit component shows it, which text.
3. **Build**: the page, the CSS, no desktop file touched.
4. **Verify**: tsc + eslint; open `/m/<path>` at 390x844 and 820x1180 (dev server `next dev --webpack -p <free port>`); no console errors; text equals the laptop text.
5. **Review**: another agent checks it (board column "reviewed by").
6. **Merge**: orchestrator merges into `main`, runs the build, pushes.
