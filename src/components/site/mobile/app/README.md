# MobileApp kit (`ma-`)

The iOS 26 design system of the phone/tablet site. A page is an *app screen*: the launcher icon is the app, the page is its screen.
One stylesheet (`app.css`, imported by `app-screen.tsx`), tokens on `.ma-root`, everything follows the visitor's theme (`--th`, `--ts`). No 3D, no canvas.

## Components (import from `@/components/site/mobile/app`)

| Component | Use |
|---|---|
| `AppScreen` | The whole screen: nav bar (Back to the launcher, small title on scroll), large title with the page's icon, content, sticky `CtaBar`. Only `ScreenChrome` (the bar) is client code. |
| `Section` | `chip`, `title` (`\n` = second line in accent colour, `*word*` highlighted), `intro`, children. |
| `Hero` | First card of a page (glass): chip, title, text, up to two buttons. `h1` when it owns the page's h1. |
| `Card` | Flat card; `tone="tint"` for the theme colour; `href` makes it a link. |
| `GroupedList` + `ListRow` | iOS inset grouped list; `ListRow` has title, text, detail, icon, `href` (chevron). |
| `Accordion` | Rows that open (FAQ), native `<details>`, no script. |
| `Stepper` | Numbered steps / timeline (`label` replaces the number, e.g. a year; `kicker`, `points`). |
| `Stats`, `Cloud`, `Chip`, `Points` | Big numbers, pills, label, check list. |
| `Gallery` + `Pic` + `PicCard` | Sideways snap row; picture in a fixed shape; card with a picture. |
| `Tabs` (client) | Scrolling capsule tabs; every panel stays in the page (`hidden`). |
| `Button` | `fill` / `tinted` / `glass` / `plain` capsule link. |
| `LeadForm` (client) | Enquiry form -> `submitLead` (Admin > Leads). |
| `CtaBar` | Floating glass bar Call / WhatsApp / Message from the real site settings. |
| `AppLink` | Link helper: external = new tab, `/` or `/#x` = launcher, app screens = client navigation, others = plain link. |
| `lines`, `pairs`, `paragraphs`, `Rich`, `Lines`, `oneLine` | Read the CMS text conventions (one per line, `Name \| text`, `*stars*`, `\n`). |

Rules: transform/opacity transitions only; `backdrop-filter` only on the nav bar, `CtaBar` and `Hero`; touch targets >= 44px; body text 16px; colours only through the `--ma-*` tokens (no hard-coded violet/pink).

## How the pages work

- `src/app/(m)/m/<path>/page.tsx` has the SAME public path as the laptop page. Generated by `node tools/scaffold-mobile-pages.mjs` (never overwrites), then `node tools/sync-mobile-ready.mjs`.
- Default: `renderMobilePage("<slug>")` (`pages/render.tsx`) reads the same CMS page as the laptop and maps each section type to `pages/sections/<type>.tsx` (registry: `pages/sections/index.tsx`, typed so no type can be missing).

## Give a page its own screen (page designers)

Work only in your page's folder and `pages/custom/<slug>/` (create it), never in the kit's shared files.

1. **Change a few section types for one page** (smallest change): write `pages/custom/<slug>/faq.tsx` etc. (a `MobileSection<"faq">`) and
   `renderMobilePage("seo", { overrides: { faq: MyFaq } })` in your `page.tsx`.
2. **A fully bespoke screen**: in your `page.tsx` call `const { page, site, sections, extra, contact } = await loadMobilePage("seo")`
   and return `<AppScreen title=... glyph=... contact={contact}>...kit components...</AppScreen>` (keep the `generateMetadata = () => mobileMetadata("seo")` line and add `<PageJsonLd>` like `renderMobilePage` does).
   Use the same words as the laptop page (the CMS data / `src/lib/cms/content/*`); no invented content.
3. Page-specific CSS: `page.css` next to your `page.tsx`, imported there, with a unique class prefix. Never edit `app.css` (ask the system owner for a kit change).
